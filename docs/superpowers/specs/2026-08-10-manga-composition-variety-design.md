# Manga Composition Variety Design

## Goal

通常の4コマ生成で、真正面・左右対称・両手をカメラ側へ広げる構図への偏りを抑え、物語と既存のカメラ指定を保ちながら斜め視点、傾き、身体のひねり、前後差のあるポーズを自動採用する。

## Root cause

- STEP2 は「ローアングル」「俯瞰」「ダッチアングル」などレンズ・高さ・傾きの種類を変えるが、被写体に対する水平方位を要求していない。
- ChatGPT/OpenAI 系の15,000文字向け圧縮では、既存の強いカメラ規則が `CAMERA: vary angles` まで縮まり、左右対称禁止が最終描画へ十分残らない。
- 両手を使うアクション、中央からの放射線、画面を埋める主役指定が重なると、画像モデルは解釈しやすい正面対称ポーズを選びやすい。

## Design

1. `src/lib/composition-variety.js` を構図多様化の単一責任モジュールとする。
   - STEP2用の日本語構図契約を提供する。
   - STEP3/4用の英語ページ全体契約を提供する。
   - Cameraタグに水平方位がないコマへ、コマ番号に応じた斜め方位を補うパネル別指示を返す。
2. 既存Cameraタグに斜め・左右・肩越し・背後などの方位が明記されている場合は上書きしない。
3. 方位が未指定の場合だけ、左前、右前、背後寄り、斜め傾斜を循環させる。
4. 4コマ全体では真正面を最大1コマ、被写体基準の方位を最低3種類とする。両手動作は肩・腰を30〜60度回転し、両手を前後にずらす。ただしActionそのもの、手の本数、小道具、話者、台詞は変更しない。
5. ChatGPT/OpenAI系とGemini系の各パネルへ同じパネル別指示を入れ、15,000文字圧縮後にもページ全体契約を保持する。

## Verification

- 回帰テストでSTEP2の通常生成指示、ChatGPT/OpenAI最終プロンプト、Gemini最終プロンプト、パネル別方位補助を検証する。
- 全Nodeテスト、ESLint、Vite build、`git diff --check` を実行する。
- 接続済みの内蔵ブラウザで通常STEP2からOpenAI APIを実行し、更新後プロンプトでSTEP4画像を生成する。
- 生成画像をフルページで確認し、4コマ中の真正面対称構図数、斜め方位数、両手動作の非対称性、人物・台詞・背景の維持を記録する。

## Out of scope

- UI追加、トグル追加、モデル変更、バージョン更新、デプロイ、リリース、バックアップ。
