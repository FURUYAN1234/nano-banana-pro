# Scenario Payoff Gate Design

## Goal

STEP2で生成した4コマを、4コマ目だけの後付け変更ではなく、1〜3コマ目の仕込みと3コマ目の読者予測を4コマ目の帰結へ接続する品質ゲートへ通す。弱い「事実提示→解説→行動→まとめの標語」を自動検出し、不合格時だけ全4コマを一度修正する。

## Accepted behavior

- ギャグ系は、欲望・誤解・矛盾の仕込み、3コマ目の予測形成、4コマ目の反転または回収、絵で分かる結果を要求する。
- シリアス系は意外性を強制せず、仕込まれた選択、代償、再解釈、余韻のいずれかを要求する。
- ドキュメンタリー系は元の事実・数値・時系列を保持し、新しい事件や事実をオチとして追加しない。
- 標語、教訓、要約、状況の言い直しだけで終わる4コマ目は不合格にする。
- 初回監査が不合格の場合だけ、監査理由を使って1〜4コマ目全体を一度修正する。
- 修正候補は既存の安全・服装・原文忠実・視覚証拠・最終コマ構図・台詞契約をすべて通し、二度目の監査にも合格した場合だけ採用する。
- 監査・修正・再監査の依存失敗または不合格では、未検証候補を採用せず元のシナリオを警告付きで保持する。
- 失敗例固有の題名、人物名、台詞、場所はproduction codeへ入れない。

## Architecture

`src/lib/scenario-payoff-quality.js`を新設し、監査プロンプト、厳格JSON解析、モード別合否判定、全4コマ修正プロンプト、1回限定の監査・修正オーケストレーションを集約する。`scenario-provider.js`は既存の安全なSTEP2候補を受け取った後にこのゲートを呼び、外部API呼び出しと既存バリデータへの接続だけを担当する。

監査結果は、`setup_seed`、`panel3_prediction`、`panel4_outcome`、`shift_kind`、`visual_payoff`、`slogan_only`、`unseeded_fact`、`reason_codes`を持つ。ギャグとシリアスで許容する`shift_kind`を分け、モデルが`pass: true`を返しても機械条件に反すれば不合格に補正する。

Web貼り付けプロンプトはアプリ外で後処理できないため、厳密寸法を保証とは表現しない。ただし圧縮時にも、選択中の標準`1120x1584`または拡大`2240x3168`と`70:99`を保持する。アプリ内API結果は従来どおり正規化後の厳密寸法をダウンロード対象にする。

## Runtime flow

1. 既存STEP2生成と同期バリデータを通す。
2. 同じ選択中シナリオモデルでWeb Searchなしの監査を1回実行する。
3. 合格なら元候補を採用する。
4. 不合格なら監査理由を添えて全4コマを1回だけ修正する。
5. 修正候補へ既存同期バリデータを適用する。
6. 通過した修正候補だけを再監査し、合格なら採用する。
7. どこかで失敗または再不合格なら元候補を保持し、STEP2ログへ具体的な警告を出す。

## Verification

- 弱い標語オチを不合格、仕込みと視覚的帰結を持つギャグを合格にするRED→GREEN回帰。
- シリアスとドキュメンタリーのモード別回帰。
- 修正は最大1回、再監査合格時のみ採用、失敗時は元候補保持のオーケストレーション回帰。
- Web短縮後にも`70:99`と選択寸法が残る回帰。
- 既存重点テスト、全Nodeテスト、警告0 lint、production build、pre-deploy。
- 内蔵ブラウザで同一題材のSTEP2を実API実行し、監査ログ、必要時の1回修正、最終4コマの仕込み・予測・帰結を目視比較する。
- API画像は標準または拡大の選択寸法と厳密70:99を確認する。Web貼り付け結果は近似出力になり得ることを区別する。
