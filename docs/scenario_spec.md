# Nano Banana Pro: シナリオパーサー仕様書 (Scenario Parser Specification)

> **目的**: 本ドキュメントは、story-maker 等の連携プロジェクトが NBP のシナリオ出力フォーマットを参照するための **公式仕様書** である。
> 実装の所在は末尾の一覧を参照すること。
> 現行v7.0.5では、STEP2の前に通常4コマと実験5〜8コマを選ぶ。各モードの構造を生成から検証・変換まで保持する。
>
> **メンテナンス義務**: パーサー仕様を変更した場合、本ファイルも **必ず同期更新** すること。

---

## 1. シナリオ出力フォーマット (Output Format)

STEP2（シナリオ生成）の出力は、以下のプレーンテキスト形式に従う。通常モード（`scenarioMode: four-panel`、既定）は4コマ固定、実験モード（`experimental-manga`）は最初から5〜8コマを作る。コマ数無指定でも実験モードは5〜8から選ぶ。通常モードで生成する際は、自由入力の総コマ数指定を採用せず4コマを保ち、1〜4コマへの有効な画風・演出指定を残す。これは入力題材の扱いであり、持ち込んだ完成台本の範囲外コマを自動で切り捨てる規則ではない。コマ番号は半角・全角数字と漢数字（一〜八）、見出しは「コマ目」「こま目」と前後の空白を受け付ける。選択モードの範囲外、欠番、重複、並べ替えは検証で拒否し、品質警告を許す経路でも通過させない。

以下は通常4コマの例。実験モードでは同じコマ内タグを使い、1から選んだ最終番号Nまで連番にする。STEP3は台本と同じコマ数・順番・台詞・画風・Cameraを保持し、4コマの引き延ばしや台詞追加を行わない。

明示台詞行の `「」` は対応必須。閉じ括弧欠損を本文として採用せず、他の有効台詞や「セリフなし」が併記されていても構造エラーにする。品質警告を許す経路でもこのエラーは通過させない。正当な入れ子引用や台詞内の人物名は削除しない。通常4コマの画像プロンプトでは本文をJSON文字列の `B1=...` として保持し、話者を尻尾メタデータへ分離する。実験モードでは各枠の `Dialogue` に台詞を保持し、`BalloonLayout` の `Bn` はその枠のn番目の台詞に対応する同じ吹き出しの配置情報であり、追加発話ではない。引用符・バックスラッシュ・制御語を含む本文は圧縮／API変換／画像QAでも往復できること。

```
Topic: [ニュースの見出し（15文字以内）]
Logline: [誰が、何を求めて、どうなるかという1〜2行のログライン]
Location: [舞台（例: 砂漠、法廷、宇宙）]
Outfit: [場所・状況に適した服装名（例: カジュアルな私服、水着、スーツ）]
Punchline: [オチの方向性（例: 爆発型、天丼爆発型、シュール、感動詐欺）]
Scenario:
[1コマ目: 起]
[EMOTION: XXX]
[Camera: XXX]
(状況とセリフ...)

[2コマ目: 承]
[EMOTION: XXX]
[Camera: XXX]
(状況とセリフ...)

[3コマ目: 転]
[EMOTION: XXX]
[Camera: XXX]
(状況とセリフ...)

[4コマ目: 結]
[EMOTION: XXX]
[Camera: XXX]
(状況とセリフ...)
```

## 2. ヘッダータグ一覧 (Header Tags)

ヘッダーと本文は `src/lib/scenario-provider.js` の生成・読み取り経路で扱い、コマ構造は `src/lib/scenario-validation.js` で検証する。タグは次の形式を使う。

| タグ名 | 正規表現 | 必須 | 説明 |
|:---|:---|:---|:---|
| `Topic` | `/Topic:\s*(.+)/i` | ✅ | ニュースの見出し（15文字以内） |
| `Logline` | `/Logline:\s*(.+)/i` | ✅ | ストーリーの軸となる1〜2行の要約 |
| `Location` | `/Location:\s*(.+)/i` | ✅ | 舞台設定（場所） |
| `Outfit` | `/Outfit:\s*(.+)/i` | ✅ | キャラクターの服装指定 |
| `Punchline` | `/Punchline:\s*(.+)/i` | ✅ | 最終コマのオチの方向性 |
| `Scenario` | `/Scenario:\s*([\s\S]+)/i` | ✅ | 選択モードの全コマ分のシナリオ本文（複数行） |

**パース順序**: `Topic` → `Logline` → `Location` → `Outfit` → `Punchline` → `Scenario` の順で抽出。`Scenario` は最後に位置し、それ以降の全テキストがシナリオ本文として扱われる。

## 3. コマ内タグ (Per-Panel Tags)

各コマ（`[1コマ目]` 〜 選択した最終コマ）の冒頭に以下のタグを付ける。

### 3.1 EMOTION タグ（感情絵柄タグ）

`[EMOTION: XXX]` 形式で各コマの絵柄スタイルを指定する。

| 値 | 説明 |
|:---|:---|
| `NORMAL` | 通常の美麗アニメ作画。日常会話、穏やかなシーン |
| `CHIBI_GAG` | ちびキャラ化（2-3頭身）。ツッコミ、呆れ、軽いギャグ |
| `GEKIGA` | 顔の彫りと細かな多方向のカケアミを強める劇画。穏やかな顔や笑顔でも造形を保ち、怒りや老化を追加しない |
| `SHOUJO` | 少女漫画風キラキラ。感動、恋愛的ときめき |
| `HORROR` | ホラー演出。恐怖、ゾッとする瞬間 |
| `BLANK` | 白目・魂抜け。衝撃、絶望、思考停止 |
| `IMPACT` | インパクトフレーム。大爆笑、大激怒、集中線 |
| `WATERCOLOR` | 人物・服・背景を淡い透明水彩で構築する。にじみ、色溜まり、紙白を生かす |
| `POP_ART` | 顔・服・背景に極太輪郭、鮮烈な平面色、大粒の規則的網点を使う印刷画風。白黒では白黒面と許可された影・素材面の網点に置き換える |
| `SKETCH` | 人物・服・背景を鉛筆線、ハッチング、紙の質感で構築する |
| `RETRO` | レトロ漫画風。昭和テイスト |
| `GLITTER` | キラキラオーラ。自信満々、ドヤ顔 |
| `SHADOW` | シルエット演出。策略、不穏、腹黒 |
| `THICK_PAINT` | 厚塗りアニメ調。重厚な表現 |
| `PASTEL` | パステルアニメ調。やわらかいタッチ |
| `CEL` | セル画風。フラットな色面、くっきりした輪郭 |
| `DARK_ANIME` | ダークアニメ調。暗いトーン、ミステリアス |
| `THIN_LINE` | 繊細線画調。極細の描線、繊細な表現 |
| `HIGH_SATURATION` | 高彩度ビビッド。鮮やかでエネルギッシュ |

### 3.2 Camera タグ（カメラ演出タグ）

`[Camera: XXX]` 形式で各コマのカメラアングルを指定する。

| 値 | 説明 |
|:---|:---|
| `俯瞰/バードアイ` | 真上から見下ろす |
| `ローアングル/アオリ` | 膝の高さから見上げる |
| `ダッチアングル` | 画面を15〜30度傾ける |
| `広角` | 奥行きの強い直線投影。自動候補に魚眼は含めず、ユーザーの明示指定のみ例外 |
| `望遠圧縮` | 遠近感の圧縮 |
| `ワームズアイ` | 地面すれすれから見上げる |
| `ドローン俯瞰` | ドローン視点の俯瞰 |
| `パンニング/追跡ショット` | 移動に追従するカメラ |

**優先順位**: Cameraの位置・上下角・レンズ・寄り引きを先に固定して人物と小道具を投影する。顔や文字を読みやすくするために明示カメラを移動しない。撮影位置が未指定のときだけ文字面の読者側へカメラを選べる。明示された撮影位置と場面内の人物・物の相対関係を保持する。画面左右は固定せず、背面への回り込みによる左右反転、遮蔽、見切れを許容する。接写や画面外を挟んでも最後の明示関係を参照し、台本に沿う移動・物の回転・場面転換では更新する。位置関係が曖昧というだけで欠陥や有料修正の根拠にしない。台詞順は吹き出しの読み順に使い、人物配置を決める根拠にはしない。肩越し構図ではCamera内で指定された手前人物（「人物名の左後方」など）を優先する。物語上必要な同一カメラの反復も許容する。

**構成時の選択**: 静かな会話にも高低差・望遠圧縮を使える。激しい感情だけに特定のカメラを限定しない。新規台本は文字を読む場面と身体演技の見せ場を考えて設計し、毎コマで全文・全員の顔・全身を同時に正面へ向ける必要を作らない。既存台本の明示文字や動作を自動的に削除しない。

**文字を読ませるコマ**: VisualEvidence の物が再登場しても、その全文を毎回読ませる義務はない。新規台本では必要な文字列を情報の提示・変化・オチに使うコマの状況へ記載し、他のコマは同じ物の側面・背面・遠景などを使える。印字は物の面に従い、吹き出し・字幕は撮影位置を拘束しない。明示された反復・可読文字・既存Cameraは保持する。STEP3の再構築だけで保存済み台本の文字指定は変更されない。

**見え方の確認**: 高さ・上下の向き、水平方位、寄り引き、レンズの遠近感は別々に指定する。肩越し・三分割・ボケという名称だけでは高低差にならない。「床から低い位置」「浅く見下ろす」等も描画用の投影指示へ補う。アオリは顔や小道具の下面、俯瞰は頭頂や天面、寄り引きは画面占有率、望遠は遠い撮影位置と長い焦点距離による背景の相対的な拡大・距離の圧縮で確認する。人物が右手を動かす記述はカメラの右方向指定ではない。明示されたアイレベル・水平撮影・反復構図は維持し、全種類を各コマへ強制しない。

**画面内の文字**: `画面文字: 「本文」`、`画面内文字`、`字幕`、`テロップ`、`キャプション`、`Screen text`、`On-screen text`、`Caption`、`Subtitle` は画面上の文字指定としてActionに保持する。登場人物・視線先・吹き出し話者には含めない。文字を置く面や場所は状況欄で指定する。

**引用と発話の区別**: `「本文」と印字された書類`、`「本文」と記された札`、`「本文」の文字を読む`は面文字として保持する。引用より後の別の動作に発話動詞があっても、引用を台詞へ昇格させない。`「本文」と叫ぶ／読み上げる`など、引用に結び付く明示発声は状況欄からも抽出し、その節の主語を話者とする。

`「本文」という記事見出し／新聞のタイトル／表題`など、文書や表示の名称を表す引用も面文字として保持する。「いう」の部分だけで発話に分類しない。`人物名「本文」`や`「本文」と読み上げる`などの明示発話は従来どおり台詞となる。

**台詞の保持**: `人物名「本文」`、同一行に並ぶ複数の話者と台詞、`「本文」（人物名）`を扱う。台詞内の括弧と入れ子の引用、意図的に繰り返した明示台詞は省略しない。話者未指定の台詞が混ざっても、後続の吹き出し番号と話者対応をずらさない。単独行の`セリフなし`等は制御指定として扱い、Actionに印刷用文字として残さない。

## 4. Punchline タイプ一覧

`Punchline` ヘッダーに指定可能なオチの方向性:

| タイプ | 説明 |
|:---|:---|
| `Auto` | AIが自動選択（デフォルト） |
| `Surreal` | 静寂型（シュール）。全員無言で固まる |
| `Explosion` | 爆発型。全員限界突破、カオス |
| `FakeEmotion` | 感動詐欺。狂った状況でイイハナシダナー |
| `Metafiction` | メタ崩壊型。第四の壁を破壊 |
| `Unreasonable` | 理不尽な制裁型 |
| `RunningGag` | 天丼爆発型。繰り返しギャグの最終形態 |
| `Dream` | 夢オチ型 |
| `PsychoHorror` | サイコホラー型 |
| `Misunderstanding` | 盛大な勘違い型 |
| `CanceledEnding` | 打ち切りエンド型 |
| `Documentary` | ドキュメンタリー（原文忠実モード） |

### 4.1 フリ・予測・帰結の監査

既存の安全・服装・事実忠実性・視覚証拠・能動アクション・台詞書式検証を通過したSTEP2候補へ、選択中のシナリオモデルで次の意味監査を行う。

- 序盤に最終コマへ効く具体的な種がある。
- 最終コマの直前までに読者が自然に予測する展開が形成される。
- 最終コマが解説・標語だけでなく、人物の行動・表情・小道具・空間変化で反転、回収、帰結、再解釈を見せる。
- ギャグは反転だけを必須にせず、規模・意味・対象・行為者が意外に増幅された帰結も許容する。
- シリアスは安いギャグ反転を強制せず、選択の結果や再解釈を許容する。
- ドキュメンタリーは元入力にない事実・数値・時系列を追加しない。

実験モードは全5〜8コマの必要性も確認する。必要な無言の間は許容し、コマ数を埋めるだけの明確な水増しを修正対象にする。人物設定と描写・話者の明白な取り違えも同じ監査で照合する。

重大な問題が根拠付きで確認された場合は、選択モードの全コマを対象に既存の一度だけの再構成を行う。修正案はコマ構造・人物・台詞などの既存検証と同じ意味監査を再度通った場合だけ採用し、失敗時は元の検証済み候補を警告付きで保持する。不確実または軽微という理由だけで有料修正を追加しない。

## 5. パーサー実装の所在

| ファイル | 主な役割 |
|:---|:---|
| `src/lib/prompts.js` | 通常4コマ／実験5〜8コマの生成指示・出力形式 |
| `src/lib/scenario-provider.js` | API応答の読み取り、生成候補・修正候補の採用境界 |
| `src/lib/scenario-validation.js` | コマ数・連番・台詞・Cameraなどの検証 |
| `src/lib/panel-utils.js` | 台詞・話者・吹き出し配置・画風の抽出 |
| `src/lib/scenario-payoff-quality.js` | 帰結・人物設定・演出・位置関係の監査と有界修正 |
| `src/lib/experimental-manga.js` | 5〜8コマと描画条件を1対1でSTEP3へ変換 |
| `src/lib/constants.js` | 画風・結末の定義と表示名 |
