# ChatGPT Work 長文入力・画像生成検証（2026-09-26）

## 結論

今回の環境では、32,000字の.txtを入力欄へ変換せず、参照画像2枚と一緒に送って画像を生成できた。Nano BananaのChatGPT系4コマ用プロンプトを15,000字へ常に圧縮する必要はない。Webコピー・.txt保存・初回OpenAI画像API送信の共通上限を、参照画像の役割説明込み32,000字に変更する。

32,000字はWebの最大値ではなく、GPT Image APIの公式上限に合わせたアプリ側の運用上限。Workでは32,001字の直接送信も成功した。文字数を増やせば画質や指示遵守が向上するという結論ではない。

## 環境・方法

- 検証日：2026-09-26 JST。ChatGPT操作は概ね07:19～07:26、調査・アプリ検証は同日07時台。秒単位の各操作時刻は記録していない。
- Windows、Codex内蔵ブラウザ、chatgpt.com、Proアカウント。Workの選択表示はGPT-6 Sol、思考「軽」。通常Chatの下書きでも比較した。独立したChrome/Edgeでは未検証。
- 文字数は生成済みUTF-8/LFのファイル本文、および貼付後のDOM本文で確認。改行込みUTF-16コード単位。今回のダミーにはサロゲートペアを含めていないのでUnicodeスカラー数と同じ。
- 本番漫画プロンプトはテスト送信していない。無害なダミーと専用の簡単な描画指示を用いた。画像生成試験だけ既存の参照画像2枚を利用した。
- テストファイルの生成スクリプト・ハッシュ一覧は作業フォルダーの `output/chatgpt-work-20260926/`。一覧の `submitted:false` は作成時点の初期値であり、実行結果は下表を正本とする。

## 最初の画像ファイルエラー

元の会話「添付画像参照エラー」では、参照エラー確認後に作業領域のファイルを調べ、「2枚とも作業領域から読み込めました」と進み、漫画が生成されている。現在取得できた参照JPEGは2枚とも686×1024で正常にデコードできた。

- **確認できた事実**：同じ会話内で読取と生成が後から成功している。今回の32,000字.txt＋同じ参照画像2枚の新規試験では再現しなかった。
- **推測**：最初に利用したパスと実際の配置先の不一致、一時ファイルの配置・参照タイミングなどは候補。
- **未確認**：失敗した実パス、当時のファイル一覧と時刻、例外スタックを取得できていないので原因は特定できない。画像破損や文字数超過が原因とも断定できない。

元の添付プロンプトはCRLF込み15,083字だが、LFに正規化すると14,943字。その元の成功だけを「15,000字超の直接入力に成功した」証拠にはしない。

## 追加の作例比較：受け付けと描画品質を分ける

利用者提供の「9秒台三連発の金」画像には、私服指定からの制服化、2・3コマ目の右側での反復横並び、指定された俯瞰・肩越しからの逸脱がある。入力プロンプトには5人それぞれの私服指定、各コマのCamera/Action、横一列禁止が残っている。2コマ目のCAST COUNTは3人だが、画像には指定外の主要人物も現れている。4コマ目のシャッター・椅子・ゲートを使う動作も生成結果とは異なる。

比較として提供された雨・情報教育・車の画像は、すべてフッターがv6.6.0で、私服と異なる画角を確認できる。雨と車の添付プロンプトにも同じWARDROBE COMPONENT LOCKと私服指定がある。教育の対応プロンプトは未提供。したがって、一律のバージョン退行や当該衣装ルール単独の原因とは断定できない。

コード差分ではv6.5.9→v6.6.0の最終圧縮に各Actionの重複衣装指定を省く処理が加わった。ただし良好な雨・車の添付にも同じ省略が見られるため、これだけで悪化を説明できない。今回の32,000字化は不要な圧縮を減らし、余裕がある本文では各コマの衣装再掲を保持する。題材による競技服への連想、参照シートの服装、固定した吹き出し位置と人物配置の競合などは検証候補であり、確定原因ではない。同一台本・同一条件の旧新比較や改善率は未検証。

## アプリ変更と検証範囲

- 4コマChatGPT系の既定予算を15,000字から32,000字へ変更。参照画像の役割説明分を構築前に予約し、AI精査も同じ予算を使う。
- Webコピー・.txt保存・初回OpenAI API送信で同じ参照説明を組み立てる。編集後を含め上限超過は明示的に拒否し、末尾や台詞を黙って切り捨てない。
- 上限未満の詳細指示は維持。超える場合の既存の意味保持圧縮は残し、それでも超える場合は停止。Gemini固有の上限をOpenAI上限へ変更してはいない。
- READMEとSTEP4の操作説明を更新。「テキストフィールドに表示」必須の案内を削除。
- 正負の境界テスト、参照2枚時のコピー/API本文一致、AI精査の予約枠、衣装再掲保持、過大入力拒否を回帰テストに追加。
- 実アプリ画面でコピーと.txt保存を操作。OpenAI向け説明の表示は本番STEP4コンポーネントの合成入力による画面確認。後者は実API検証として数えない。
- 今回の画像生成実測はChatGPT Work。改修後の漫画品質改善と実APIでの32,000字新規画像生成は未検証。

## 今後の手順

1. Nano Bananaの最終プロンプトをコピー、または同じ内容を.txtで保存する。ChatGPT系は参照説明を含め32,000字以内。
2. 新しいWork会話へ.txtとキャラクターシート2枚を添付。画像はアプリの順番を守り、背景がある場合は最後に添付する。
3. 全ファイルの読み込み完了を待ち、「添付テキスト全文を画像生成指示として読み、添付画像を人物参照として生成してください」と送る。テキストフィールドへの変換は今回の運用では不要。
4. 読取エラー時は実際の添付・ファイル名を確認し、見つからない添付だけを再送する。推測したローカルパスへ誘導しない。
5. 生成後に人数、私服・指定衣装、画角、動作、台詞を確認する。ファイルを読めたことを品質合格と扱わない。
