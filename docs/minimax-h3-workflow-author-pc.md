# MiniMax H3 ワークフロー作成・検証PC用 APIキー取扱手順

この手順は、MiniMax H3ワークフローを作成・編集・検証・配布するPCで必ず実施する最重要チェック項目です。APIキー値そのものを確認、表示、コピー、記録する手順ではありません。

## 作業前

1. ComfyUIアプリとComfyUIサーバーを完全に終了します。
2. 旧版が作成した旧資格情報ファイル `ComfyUI/user/nanobanana_h3_credentials.json` が残っていないか、存在の有無だけを確認します。旧資格情報ファイルを見つけても、中身を開かず、画面へ表示せず、コピーやバックアップをせずに削除します。
3. 旧版で平文保存した可能性があるAPIキーは、各Providerの管理画面で失効・再発行します。キー値をチャット、作業ログ、メモ、スクリーンショットへ貼り付けません。
4. `ComfyUI-NanoBanana-H3` はComfyUI停止中にフォルダ単位で差し替えます。旧版と新版のファイルを混在させません。

## 動作確認

1. ComfyUIを起動し、対象ワークフローを開きます。
2. ワークフローを開いただけではAPI入力ダイアログが表示されないことを確認します。Providerを変更した時も、状態表示だけが更新されて入力ダイアログが表示されないことを確認します。
3. 「実行する」を押します。選択中Providerが未登録なら、そのProviderのAPI入力ダイアログが開き、キュー投入が保留されることを確認します。
4. APIキーは利用者がダイアログへ直接入力します。入力後、状態表示にキー値や一部文字列が出ず、認証成功後に保留中の同じ実行が1回だけ続くことを確認します。
5. 別の未登録状態で実行し、入力ダイアログを閉じた場合は今回の実行だけが中止されることを確認します。
6. 同じComfyUIプロセスのままワークフローのシート移動または別ワークフローへの切替を行い、登録状態が保持されることを確認します。
7. ComfyUIアプリ／サーバーを終了して再起動し、同じワークフローを開きます。開いただけでは入力ダイアログが出ず、「実行する」を押した時に再び入力ダイアログが開くことで、前回のキーが消去されたことを確認します。
8. 旧資格情報ファイルが再作成されていないことを、存在確認だけで検証します。APIキー値を検索、表示、記録しません。

## 配布前

1. ワークフローJSON、配布ZIP、設定ファイルへAPIキーをシリアライズしていないことを確認します。
2. 外側ZIPだけでなく全ネストZIPを展開し、旧資格情報ファイル名、ファイル読書き処理、APIキー形式らしき値、旧い保存説明が含まれないことを自動検査します。
3. README、仕様、ワークフロー内Markdown、画面説明を、次の同一契約へそろえます。
   - キーは動作中のComfyUIサーバープロセスのメモリだけに保持する。
   - ワークフローのシート移動では保持する。
   - ComfyUI終了・再起動で消去する。
   - ワークフロー読込時やProvider変更時には入力ダイアログを表示しない。
   - 「実行する」を押した時、選択中Providerが未登録なら入力ダイアログを開いて実行を保留する。
   - 認証成功後は同じ実行を1回だけ続け、ダイアログを閉じた場合は今回の実行だけを中止する。
   - 認証確認または実行時だけ、接続中のComfyUIサーバーから選択Providerへ送信する。
4. APIキー値を表示・記録・配布していないことを確認し、回帰テスト、構文検査、配布ZIP実体検査がすべて通るまで公開しません。
