# v8.0.0

An MCP-compatible AI client can now call the manga application's shared production engine. The bundled production skill takes a brief through character references, synopsis, detailed-plan approval and ordered page generation. The application retains projects, shared assets and per-page state; each completed page is saved to Downloads as PNG plus matching production JSON. / MCP対応のAIから、漫画アプリの共通制作処理を呼び出せるようにしました。同梱の制作スキルで、ざっくりした依頼から人物資料、あらすじ、詳細台本の確認、ページ順の生成へ進めます。作品・共通資料・ページごとの状態を保持し、完成したページからPNGと同名の制作情報JSONをダウンロードフォルダーへ保存します。

Before production or resuming, the AI calls `manga_save_status(projectId)` to check automatic saving and the destination. MCP saves page PNG/JSON pairs, shared materials and the whole-book manifest directly; no browser download setting or folder picker is required. The tool distinguishes unsaved, missing, hash-mismatched and unreadable files using saved-file readback. It does not claim browser download permission is granted. Do not repeatedly ask the user to select the same destination. / AIは制作・再開の前に `manga_save_status(projectId)` で自動保存と保存先を確認します。MCPはPNG・JSON、共通資料、作品全体JSONを直接保存するため、ブラウザーのダウンロード設定やフォルダー選択は不要です。保存ファイルを読み戻し、未保存・欠落・ハッシュ不一致・読取不能を区別します。ブラウザーの保存許可を確認済みとは扱わず、同じ保存先の選択を繰り返し求めません。

For troubleshooting, `manga_job_get` can return sanitized `error.failureContext`. Request `manga_run` with `operation:"read_state"` and `input:{includeDiagnostics:true}` for an opt-in, bounded diagnostic summary from the connected browser origin, including ordinary single-page troubleshooting. Keys and image bodies are excluded; omitted context is identified, and warnings are distinct from failed jobs. / 不具合調査では `manga_job_get` の安全化済み `error.failureContext` を確認できます。`manga_run` に `operation:"read_state"` と `input:{includeDiagnostics:true}` を指定すると、接続中ブラウザーの同じURLの診断要約を明示的に取得し、通常1ページの不具合調査にも使えます。キー・画像本体を除き、容量上限による省略と、警告・失敗を区別します。

Book-detail authoring may add natural speech while preserving exact supplied lines and explicitly silent scenes; it does not require dialogue in every panel. It carries forward a bounded summary of the preceding page’s location, outfits and final object state, while explicit current-page scene, time or costume changes take priority. An unrequested entirely silent book draft is rejected; ordinary single-page and imported-source handling are unchanged. / 複数ページの詳細台本では、指定済みの台詞と明示された無言の場面を守りつつ、自然な会話を補えます。各コマへの台詞は強制しません。前ページの場所・衣装・最後の小道具の状態を長さ制限付きで引き継ぎ、当ページに明示した場面・時刻・着替えを優先します。依頼のない全編無言の案は拒否し、通常1ページや取り込み原文の扱いは変えません。

OpenAI book pages support 1–8 panels, color or monochrome, illustrated covers or a large opening panel with a title logo, page numbers and ending lettering over the final panel. Canonical character, prop and background references carry across pages, with the previous completed page as an auxiliary reference. The skill normally adds the two standard footer credits only to the final page; explicit display preferences remain independent. / OpenAIの複数ページ制作では1～8コマ、カラー・白黒、1枚絵表紙や上半分大コマと題字、ページ番号、最後のコマに重ねる終幕文字を扱います。人物・小道具・背景の基準資料を引き継ぎ、前ページの完成画像を補助資料にします。スキルの標準では通常の2種類のウォーターマークを最終ページの下だけに付け、個別の表示指定を優先します。

Choose ending words such as “END”, “おしまい” or “おわり” to suit the story, preserving an explicitly selected string. Place them inside the final panel at lower-right; if occupied, use lower-center, then lower-left, with lettering matching the title’s mood. Keep faces, necessary actions, dialogue, page numbers and footer marks readable. / 終幕語は漫画に合う「END」「おしまい」「おわり」等を選び、明示した文字列はそのまま保ちます。最終コマの右下を基本に、空きがなければ下中央、次に左下へ置き、タイトルの雰囲気に合う字体を使います。顔・必要な動作・台詞・ページ番号・下端の表示を隠しません。

The Windows launcher and skill share verified installation and update logic. A running production session is preserved. MCP control greys out manual inputs and settings while keeping scrolling and results readable; one “Stop and return to manual” button settles local work before unlocking. The MCP controls, skill download, guides, diagnostics and Model Chain share the top row. The four production steps and loop/full-auto controls each have their own row. / Windowsランチャーとスキルは、取得元とファイルを検証する同じ導入・更新処理を使い、制作中の接続を保ちます。MCP操作中は手動の入力・設定欄を灰色にし、スクロールと結果の閲覧は続けられます。「停止して手動に戻る」1つで処理を止めてからロックを解除します。MCP操作、スキル取得、ガイド類、不具合調査ログ、Model Chainを上段にまとめました。STEP1～4の進捗とループ／全自動の切り替えは、それぞれ独立した行へ整理しました。

The Codex-oriented skill guides API entry when needed and enables AI control when browser operation is available; other clients receive explicit manual steps. It asks which author name to put on the cover, or whether to omit it. Matching PNG/JSON names include the title, page number and local date/time down to seconds, and both files are committed together. / Codexを主な利用先とするスキルは、必要な時点でAPI入力を案内し、ブラウザーを操作できる場合はAI操作を有効にします。他の環境では必要な操作を説明します。扉の作者名は本人に確認し、表記なしも選べます。PNG・JSONはタイトル・ページ番号・年月日時分秒を含む同名とし、両方を揃えて保存を確定します。

Deliverables are grouped in a folder named for the book and its start time. Page pairs sit alongside `作品全体.json`; character sheets, props and backgrounds are collected under `資料/`. Available production records include models, versions, times, plans, approvals and file hashes. Unverified sources and permissions are explicitly unconfirmed. / 成果物は作品タイトルと開始日時のフォルダーへまとめます。各ページの画像・JSONと`作品全体.json`を直下に置き、人物シート・小物・背景は`資料/`へ整理します。確認できたモデル・版・日時・台本・承認・ファイルのハッシュを制作記録に残し、素材の出典や許諾が未確認ならその状態を明記します。

Ordinary single-page API results also keep the PNG and matching production JSON in a work folder with title, page and date/time in their names. An explicitly selected parent folder is used when supported; otherwise one ZIP contains the same folder and pair. Both use the same sanitized generation-time record. / 通常の1ページAPI生成も、作品名・ページ番号・年月日時分秒を含む同名のPNGと制作情報JSONを、作品フォルダーにまとめます。対応環境では事前に選んだ親フォルダーへ保存し、それ以外は同じフォルダーを含むZIPを1件ダウンロードします。両ファイルには生成時点の同じ安全化済み記録を使用します。

Ordinary OpenAI creation remains free composition with 4–8 panels; Gemini keeps its four-panel route. The legacy four-strip selector is hidden while its internal implementation is retained. README, the MCP guide, the downloadable skill and all three PDF manuals describe the new workflow. MCP requires a local service and an open, connected local application; the hosted demo alone does not start it. API keys stay in the application's normal connection UI. / 通常のOpenAI制作は自由配置の4～8コマ、Geminiは4コマの経路を維持します。旧横長4段の選択スイッチは非表示にし、内部処理を残しました。README、MCP説明書、配布スキル、PDF3冊へ新しい使い方を反映しています。MCPにはローカルサービスと、開いて接続したローカル制作画面が必要です。公開デモだけでは起動せず、APIキーは通常の接続画面へ入力します。

Shared-material exports serialize readable-name assignment so concurrent saves cannot assign one filename to different assets. Page preparation and recognition use the target project context and isolate restored history, preventing references from an earlier project from entering its snapshot or portable manifest. If saving or recognition fails, inspect the original job and `manga_save_status` before retrying; a completed API response alone does not establish a saved result. / 共通資料の保存名は同時処理でも割当を直列化し、異なる資料へ同じ名前を割り当てません。ページ適用・認識では対象作品の文脈と復元履歴を分離し、前の作品の資料がスナップショットや持ち運び用の全体JSONへ混ざるのを防ぎます。保存・認識の失敗時は再試行前に元jobと `manga_save_status` を確認し、API応答の完了だけを保存成功とは扱いません。

Book-page title, location and outfit metadata are carried into the shared STEP3 drawing instructions and review context even when the approved scenario contains only panel bodies. This preserves the approved script while preventing a missing page title or a return to cast-default clothing merely because the header metadata was absent. Actual image acceptance is still separate. / 承認済み台本がコマ本文だけの場合も、ページ別の題名・場所・衣装を共通STEP3の描画指示と検査へ引き継ぎます。承認台本を変えず、見出し情報の欠落だけで題名が無題になったり、人物設定の標準衣装へ戻ったりするのを防ぎます。実画像の受け入れ確認は別途行います。

MCP scenario generation follows the selected manual/news input mode, including the configured news categories and date. Manual text is kept literal; empty manual input or missing news categories stops before a provider call. / MCPの台本生成は自由入力／ニュースの選択に従い、ニュース分類と日付を引き継ぎます。自由入力は原文を保ち、空入力やニュース分類未選択はAPI送信前に止めます。

Scenario payoff repair now preserves an existing PageComposition JSON line verbatim while repairing the scenario body, so repaired native pages keep their layout contract. The legacy four-panel non-JSON path is retained. / 台本の結末修復では既存のPageComposition JSON行を逐語で保持し、本文だけの出力要求によって自由配置の構成情報を失わないようにしました。従来のJSONを持たない4コマ経路は維持します。
