# Nano Banana Pro v6.5.5

## 日本語

- API画像の自動品質修正で作られた途中候補は内部比較だけに使い、ユーザー向けの生成履歴には各生成の最終採用画像1件だけを残すよう修正しました。
- 初回候補と最大3回の修正候補を比較する場合も、最終プレビューと生成履歴は同じ採用画像を示します。
- 実APIで初回候補＋修正3候補まで走らせ、最良候補の選択後も生成履歴が1件だけであることを確認しました。

## English

- Automatic image-quality repair candidates are now used only for internal comparison, while user-facing generation history keeps only the final accepted image from each generation.
- Even when the initial candidate is compared with up to three repairs, the final preview and history now point to the same accepted image.
- Verified with a live API run that exercised the initial candidate plus three repairs and still left exactly one user-visible history entry after selection.
