# Nano Banana Pro v6.6.3

## 日本語

- 長文プロンプトの圧縮を約15,000字から始める方式に戻しました。安全に削れる重複を先に短くし、台詞、構図、人物識別、画風に必要な指定は残します。15,000字は目安で、必要なら超過します。参照画像の説明を含む32,000字はAPI上限です。
- STEP4の分割コピーは9,500字以下で行境界を優先して区切ります。番号順に同じ入力欄へ続けて貼ると、改行を含めて元の全文へ戻ります。特定の見出しを分割点として固定していません。
- 全コード監査で確認した台詞とコマ見出しの扱い、安全化時の否定形と印字文の保護、検索必須経路、API応答の完了判定と待ち時間、画像QAの未確認判定、非同期処理の競合、生成履歴の制作情報などを修正しました。
- 全Nodeテスト、警告なしlint、production buildを確認しました。実APIでは参照シート2枚を使い、2240×3168のカラー4コマを生成して目視確認しました。画像QAには人物識別などの未確認項目が残ります。旧版との同条件比較は実施しておらず、画質向上や完全な指示遵守は保証しません。

## English

- Restored early safe compaction around a soft 15,000-character target. Required dialogue, camera, character identity and rendering instructions remain even when the result exceeds that target. The 32,000-character API ceiling includes reference-image instructions.
- STEP4 split-copy chunks are at most 9,500 characters and prefer line boundaries. Pasting them in order into one composer reconstructs the full prompt, including newlines; no heading is hardcoded as a split point.
- Fixed audited defects in dialogue and panel parsing, preservation of negation and printed text during safety conversion, search-required routing, API completion and timeouts, uncertain image-QA verdicts, asynchronous state races, and generation-history provenance.
- The full Node suite, zero-warning lint and production build passed. One live API generation with two reference sheets produced a 2240×3168 color four-panel page inspected visually. Character-identity evidence remains unverified in app QA. There was no controlled old-versus-new image comparison, so this release does not claim improved image quality or perfect instruction adherence.
