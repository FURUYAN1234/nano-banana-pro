# Nano Banana Pro v7.0.6

STEP3 now repairs inconsistent balloon placement in both four-panel and 5–8-panel scenarios. Only affected placement fields may change; dialogue, actions, camera directions, panel count and order are retained. Invalid repairs preserve the original script and report the failure. The repaired scenario is passed to subsequent generation, including full-auto workflows.

The panel-count control is now a slide switch: left light blue “4コマ生成”, right green “5～8コマ生成”, with a white thumb moving between them. Help text and documentation use the same names, and switching retains each mode’s existing work.

Long 5–8-panel prompts compact repeated app instructions before reaching the API limit, while retaining authored camera directions, acting, expressions, dialogue and per-panel styles. Camera height, direction, framing and scene roll remain independent; rear views follow the scripted spatial relationships. Rendered compliance still varies by generation.

Image review retains independent observations and reports insufficient evidence as unverified. Explicit clothing instructions take precedence over reference-sheet outfits. Multi-stage review uses each API request’s timeout instead of a cumulative cutoff, and preserves the generated image if review fails or remains uncertain.

STEP3は4コマ・5～8コマの両方で、吹き出し配置の不整合を修復します。変更できるのは問題のある配置だけで、台詞・状況・カメラ・コマ数・順序は保持します。不正な修復案は拒否して元台本を残し、理由を表示します。修復した台本を、全自動を含む後続の生成へ引き継ぎます。

コマ数選択を、左が水色の「4コマ生成」、右が緑色の「5～8コマ生成」となるスライドスイッチへ変更しました。白い丸が左右に動き、説明文とマニュアルも同じ呼び名に揃えています。各モードの作成済み台本・結果を保持して切り替えられます。

5～8コマの長い指示文は、API上限に達する前にアプリ側の重複説明を圧縮します。元のカメラ・演技・表情・台詞と各コマの画風を保持し、撮影の高さ・方向・画角・場面の傾きを分けて扱います。後方から見える人物の面は、台本の位置関係から指定します。画像への反映には生成ごとの差があります。

AI検査は画像の観察内容を残し、根拠不足を未確認として表示します。衣装は参照シートより台本の明示指定を優先します。複数段階の検査は累積時間ではなく各APIの応答上限で待ち、失敗・未確認でも生成画像を保持します。
