# Nano Banana Pro v6.3.7

## 日本語

漫画のシナリオ、Web貼り付け用プロンプト、API画像生成後の検査をまとめて強化しました。

- ギャグとシリアスの4段階構成を分け、両方のドキュメンタリーを各メニュー内に配置しました。ギャグは視覚的な反転と回収、シリアスは損失・選択・行動・余韻を重視します。
- Acting Identity Lockを追加し、人物ごとの姿勢、身振り、視線、物を確かめる癖を別々の行動として維持します。
- 明示した衣装を時代・文化・背景より優先します。衣装指定がない場合だけ、場所と時代から自然に推定します。
- 主役へ強いGペンタッチと焦点を集め、脇役と背景の情報量を抑えます。後頭部、首、手足、関節、小道具の持ち主と接触も検査対象にしました。
- 物語上必要な新キャラクターを人数へ含め、再登場時の外見、服装、小道具、位置、動作を保持します。
- 出典や説明文を吹き出しへ入れず、台詞、看板、包装、本、画面などの実文字を画像から独立して照合します。
- カラーと白黒の共通プロンプトを整理し、白黒では純白・黒・範囲限定の網点と強いGペンを使います。
- API失敗や修正上限後も、検査済みの最良候補を警告付きで保持して処理を続けます。コンテンツポリシー拒否時は台本を壊さない最小限の表現調整を行います。
- 次に押せるSTEPボタンを穏やかな明暗変化で案内します。既存画像のQA再検査は、自動修正ONかつ明確な不合格時だけ、元画像ダウンロードの直下へ表示します。
- READMEを現行機能、物語アルゴリズム、モデル経路、画像QA、再試行、制約まで含む内容へ更新しました。

実APIではGPT-6 Astraによるシリアスシナリオと、GPT Image 2.5 Sunburst/xhighによるカラー・白黒4コマを確認しました。白黒は吹き出し位置の修正候補を比較し、読順を悪化させない画像を採用しています。

## English

This release strengthens the scenario routine, Web-copy prompt and post-generation image review as one workflow.

- Gag and serious stories now use separate four-beat structures, with documentary variants placed inside their respective menus.
- Acting Identity Lock preserves character-specific posture, gesture, gaze and object-check habits through varied actions.
- Explicit outfits override the setting era, culture and background; clothing is inferred from the setting only when no outfit is supplied.
- Stronger G-pen hierarchy and focal control reduce secondary clutter. Rear-facing heads, joints, limbs, prop ownership and physical contact are reviewed explicitly.
- Story-required guests count toward each panel and retain identity, clothing, props and spatial continuity when they recur.
- Source metadata stays outside speech bubbles. QA independently transcribes visible dialogue, signs, packaging, books and screens from rendered pixels.
- Color and monochrome share the same story contracts; monochrome uses pure white, solid black, bounded screentone and forceful G-pen linework.
- Bounded retries retain the best inspected candidate with a warning. Policy-repair requests make the smallest compliant wording change without rewriting the script.
- A restrained brightness pulse identifies the next STEP. Existing-image QA appears below the original-image download only when automatic repair is enabled and the current image has a definite failure.
- The README now documents the complete current feature set, story algorithm, model routes, image QA, retry behavior and limitations.

Live API validation covered a GPT-6 Astra serious scenario and matched color and monochrome four-panel pages generated with GPT Image 2.5 Sunburst/xhigh. The monochrome run compared repair candidates and retained the version that preserved right-to-left bubble order.
