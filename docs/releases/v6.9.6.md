# Super FURU AI 4-koma System v6.9.6

## English

STEP1 now recognizes mixed character sheets, expression/turnaround views, backgrounds and props together, and shows their results in one always-visible editable/copy field. The file-selection button and whole-STEP1 drop area both support later additions. Thumbnail hints start with the current image number; text and spacing are compact.

- Ordinary material images share 14 slots. With a 360° background enabled, use up to 10 ordinary images plus one original panorama. Style JSON is excluded. Over-limit additions retain the existing material and settings.
- Web generation uses all the same original images in the current STEP1 display order. A panorama always appears last and is renumbered after later ordinary additions. API generation maps references automatically.
- Explicit STEP2 material and panel instructions take priority. Otherwise the panorama anchors the setting; ordinary backgrounds remain available where the story uses them. Attachment order maps numbers, not background priority.
- Free input can specify material use/exclusion, holder, action and state. AI arranges unclear or conflicting wishes into a coherent scene where possible. Recognition and rendering may omit, confuse or leave material unused; complete reproduction is not guaranteed.
- The right footer preserves the scenario model and names the selected image engine first, for example `ChatGPT Images 2.5 / GPT-6.1 Sol / FURU AI 4-koma v6.9.6`. API and Web-copy instructions share this attribution; existing images are retained.
- Repeated reference policies are emitted once per material type. In the checked seven-image case, the OpenAI send body decreased from 29,151 to 27,678 characters while retaining individual reference facts and scripted visual directions.
- Updated the app guidance, English/Japanese README and all three PDF guides. Manual page-number validation rejects stale totals.

Live validation used normal OpenAI STEP1–4 paths with character sheets, ordinary backgrounds, a key and a synthetic 360° panorama. Panorama numbering shifted from image 8 to image 9 after a later ordinary addition. Fresh scenarios reflected material exclusion, panel locations, key ownership and sequential hand actions. The final v6.9.6 image completed in 241 seconds at 2240×3168 with automatic repair OFF; its image-engine/scenario-model footer and mixed-reference reflection were visually checked. Existing camera, surface and observation-evidence warnings remain. This update does not claim universal image-quality approval or a paid Gemini-image validation.

## 日本語

STEP1で人物・表情集・三面図・背景・小物をまとめて認識し、一つの常時表示する編集・コピー欄へ統合しました。ファイル選択ボタンとSTEP1の枠内全体へのドロップを併用でき、後からも追加できます。サムネイルの説明は現在の通し番号から表示し、文字と余白を詰めました。

- 通常の素材画像は合計14枚まで。360°背景ONでは通常素材10枚＋元の360°画像1枚までです。作風JSONは枚数に含めず、超過追加では既存素材と設定を保持します。
- Webには同じ元画像をすべて、STEP1の現在の表示番号順で添付します。360°画像は常に最後へ表示し、通常素材の後追加に合わせて番号を更新します。APIではアプリが対応づけて送ります。
- STEP2の素材・コマ別指定を優先します。指定がなければ360°背景を舞台の基準にし、2D背景も場面に合う範囲で使います。添付順は画像番号の対応づけであり、背景の優先順位ではありません。
- 自由入力で採用・除外、持ち主、動作・状態を指定できます。曖昧・矛盾する希望はAIができる範囲で場面へ整理します。認識できない場合や取り違える場合、今回のまんがには使用しない場合もあります。完全再現は保証しません。
- 右フッターには、現在の画像生成エンジン名、シナリオモデル名、アプリ名・版を併記します。APIとWebコピーへ共通で反映し、生成済み画像は保持します。
- 共通の素材ルールを種類ごとに一回へまとめました。確認した7枚の例では、個々の特徴と台本の描画指示を残し、OpenAI送信文を29,151文字から27,678文字へ減らしました。
- アプリ説明、英語／日本語README、3冊のPDFを更新し、PDFの総ページ数の不一致も検出するようにしました。

実API検証は人物資料・通常背景・鍵・サンプル360°背景を通常のOpenAI STEP1～4で読み込みました。360°背景の後へ通常素材を追加すると画像8から画像9へ更新されること、素材の除外・コマ別背景・鍵の持ち主・手の動作の順序が新規台本へ反映されることを確認しました。最終v6.9.6画像は自動修正OFF、2240×3168で241秒で完了。素材の反映と画像エンジン名＋シナリオモデル名のフッターを目視しました。構図・物体面・観察証拠には既存の未確認警告が残り、全面的な品質合格やGeminiの課金画像検証を完了したものではありません。
