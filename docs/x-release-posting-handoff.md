# アプリ更新時のX・Facebook告知／他PC引き継ぎ（全アプリ共通）

## 適用範囲と投稿判断

この手順はNano Banana Pro専用ではない。このPCで継続的に更新しているアプリ、Gitで管理しているアプリ、このPCからデプロイ・リリースしているアプリ全般に適用する。他PCで同じプロジェクトを引き継ぐ場合も適用する。個々のアプリのGitHubリポジトリやnote記事は、そのアプリのREADME・HANDOFF・公開画面で毎回特定する。

ユーザーは2026-09-26に、今後、アプリの実質的な更新をnoteで案内する際はXとFacebookにも同じ文章で告知するよう依頼した。新機能、利用方法の変更、大きな使い勝手の改善、重要な不具合修正は原則として告知する。誤字や数pxの調整など、利用者への説明を要しないごく小さな修正はSNS告知を省略できる。note更新がなくてもSNSで知らせる価値のある節目を見つけたら、理由と投稿案をユーザーに提案する。別アプリの更新をNano Banana Proの記事やリンクで代用しない。

## 公開先と順番

1. 対象アプリ、今回公開された変更、公開アプリまたは配布先、対応するnote記事を特定する。未公開の変更を公開済みとして書かない。
2. ユーザーが依頼したデプロイ・リリースとnote更新をそれぞれ完了し、公開ページで変更点とリンク先を読み戻す。noteだけの更新なら、新たなデプロイを勝手に実行しない。
3. **見出し、変更点、対象アプリの公開URL、対応するnote記事のURL、関連ハッシュタグ** の順に改行した共通の投稿文を1件作る。アプリ固有のnoteがなければ、別アプリの記事を載せず、確認済みの公式案内先を使う。
4. Xの [@FURUYAN123456](https://x.com/FURUYAN123456) に投稿する。Facebookはユーザー指定の個人プロフィールへ、公開範囲を **友達（一部除外）** にして、**同じ本文・URL・ハッシュタグ・改行**で投稿する。送信前にアカウントと公開範囲を画面で再確認し、別件の既存下書きを上書きしない。
5. Xでは文字数カウンター、Facebookでは投稿先と公開範囲を含め、両方の本文・改行・全URLを送信前に確認する。送信後は各投稿の固有URLを開いて読み戻す。Facebookの「友達（一部除外）」投稿は閲覧範囲外には表示されない。成否が不明な場合は各投稿先の最新投稿を先に確認し、重複投稿を避ける。

別PCではCodex内蔵ブラウザを優先し、X・Facebookに未ログインならユーザーがそのPCでログインする。ログイン状態やFacebookの公開範囲をPC間で引き継げる前提にしない。Facebookでは個人プロフィールと「友達（一部除外）」を毎回確認する。SNS投稿はアプリのデプロイ、note更新、フルバックアップを新たに実行する許可にはならない。

## 文面と安全確認

- アプリの利用者向け名称は、該当アプリの公開ページとnote記事の現行見出しに合わせる。リポジトリの内部管理名だけで告知しない。
- 実際に公開・確認した改善だけを書く。画質向上、完全再現、API上限、料金など、未検証の成果を約束しない。
- XとFacebookの自動折り返しと、投稿データの実際の改行を区別して確認する。文章の途中に不自然な改行を入れない。ハッシュタグは内容に合うものを2～3個程度に絞る。Xの文字数に収まる共通文面を作り、Facebook用に勝手に言い換えない。
- 個人情報、連絡先、APIキー、パスワード、認証コード、Cookie、ローカルパス、内部ログ、未公開の入力・画像、未確定の障害原因を投稿・引き継ぎ書・Gitに含めない。送信前に本文とURLを照合する。
- noteのカードプレビューが古い見出しを表示する場合は、必要ならカードだけ外して本文のnoteリンクを保持する。
- 完了記録には、対象アプリ、XとFacebookそれぞれの投稿URL・投稿アカウント・Facebook公開範囲、実際の本文と改行、リンク先、Xの送信前の残り文字数、読戻し結果を残す。Facebook個人プロフィールの実名や固有URLを公開Git文書に書かず、ユーザーへの納品時に直接提示する。固有URLが得られない投稿は完了扱いにしない。

## 2026-09-26のNano Banana Pro実例

この実例のURLと文面を他アプリへ流用しない。v6.6.2は [このX投稿](https://x.com/FURUYAN123456/status/2103763061962359058) で告知した。送信前のX標準カウンターは残り6文字。noteカードの旧版プレビューを外し、公開本文・2リンク・3ハッシュタグ・改行を読み戻した。

```text
【完全自立型AIまんがエンジン更新】
「Super FURU AI 4-koma System」のWeb貼り付け画面を改善。分割コピーの順番と完了表示、全文の文字数、TXT保存と制作情報JSONの違いを明示しました。
アプリ：https://furuyan1234.github.io/nano-banana-pro/
解説：https://note.com/happy_duck780/n/ndf063558c1f5
#AIまんが #4コマ漫画 #ChatGPT
```

この投稿ではXホームの入力欄に下書きが残る場面があった。送信済み通知と公開ポストの両方を確認し、入力中に別のキー入力が混ざったため送信前に全文を照合し直した。Nano Banana Proのリリース・note・フルバックアップの証拠は [同アプリのHANDOFF](../HANDOFF.md) 冒頭にある。この文書の更新は当時のバックアップZIPより後なので、他PCではGitの履歴から取得する。

同じ文面をFacebookの個人プロフィールにも投稿した。別件の下書きを保持するため新しいタブで作成し、送信前と投稿後に **友達（一部除外）**、本文5行、2リンク、3ハッシュタグを確認した。投稿の固有URLはユーザーへの納品で直接提示し、個人プロフィールを識別できるため公開Gitには載せない。他PCではこのPCのログイン状態を流用せず、同じプロフィールと公開範囲を確認する。
