# アプリ更新時のX告知・他PC引き継ぎ（全アプリ共通）

## 適用範囲と投稿判断

この手順はNano Banana Pro専用ではない。このPCで継続的に更新しているアプリ、Gitで管理しているアプリ、このPCからデプロイ・リリースしているアプリ全般に適用する。他PCで同じプロジェクトを引き継ぐ場合も適用する。個々のアプリのGitHubリポジトリやnote記事は、そのアプリのREADME・HANDOFF・公開画面で毎回特定する。

ユーザーは2026-09-26に、今後、アプリの実質的な更新をnoteで案内する際はXにも告知を追加するよう依頼した。新機能、利用方法の変更、大きな使い勝手の改善、重要な不具合修正は原則として告知する。誤字や数pxの調整など、利用者への説明を要しないごく小さな修正はX投稿を省略できる。note更新がなくてもXで知らせる価値のある節目を見つけたら、理由と投稿案をユーザーに提案する。別アプリの更新をNano Banana Proの記事やリンクで代用しない。

## 公開先と順番

1. 対象アプリ、今回公開された変更、公開アプリまたは配布先、対応するnote記事を特定する。未公開の変更を公開済みとして書かない。
2. ユーザーが依頼したデプロイ・リリースとnote更新をそれぞれ完了し、公開ページで変更点とリンク先を読み戻す。noteだけの更新なら、新たなデプロイを勝手に実行しない。
3. Xの [@FURUYAN123456](https://x.com/FURUYAN123456) に、今回の対象アプリ名と利用者に伝わる変更点を記した投稿を1件作る。送信前に表示中のXアカウントを確認する。
4. 投稿文は **見出し、変更点、対象アプリの公開URL、対応するnote記事のURL、関連ハッシュタグ** の順で、それぞれ明確に改行する。アプリ固有のnoteがなければ、別アプリの記事を載せず、確認済みの公式案内先を使う。
5. Xの文字数カウンター、本文、改行、全URL、アカウントを送信前に確認する。送信後は公開ポストの固有URLを開き、同じ項目を読み戻す。成否が不明な場合はプロフィールの最新投稿を先に確認し、重複投稿を避ける。

別PCではCodex内蔵ブラウザを優先し、Xに未ログインならユーザーがそのPCでログインする。ログイン状態をPC間で引き継げる前提にしない。X投稿はアプリのデプロイ、note更新、フルバックアップを新たに実行する許可にはならない。

## 文面と安全確認

- アプリの利用者向け名称は、該当アプリの公開ページとnote記事の現行見出しに合わせる。リポジトリの内部管理名だけで告知しない。
- 実際に公開・確認した改善だけを書く。画質向上、完全再現、API上限、料金など、未検証の成果を約束しない。
- X上の自動折り返しと、投稿データの実際の改行を区別して確認する。文章の途中に不自然な改行を入れない。ハッシュタグは内容に合うものを2～3個程度に絞る。
- 個人情報、連絡先、APIキー、パスワード、認証コード、Cookie、ローカルパス、内部ログ、未公開の入力・画像、未確定の障害原因を投稿・引き継ぎ書・Gitに含めない。送信前に本文とURLを照合する。
- noteのカードプレビューが古い見出しを表示する場合は、必要ならカードだけ外して本文のnoteリンクを保持する。
- 完了記録には、対象アプリ、公開ポストURL、投稿アカウント、実際の本文と改行、リンク先、送信前の残り文字数、公開読戻し結果を残す。公開URLが得られなければ投稿済みと記録しない。

## 2026-09-26のNano Banana Pro実例

この実例のURLと文面を他アプリへ流用しない。v6.6.2は [このX投稿](https://x.com/FURUYAN123456/status/2103763061962359058) で告知した。送信前のX標準カウンターは残り6文字。noteカードの旧版プレビューを外し、公開本文・2リンク・3ハッシュタグ・改行を読み戻した。

```text
【完全自立型AIまんがエンジン更新】
「Super FURU AI 4-koma System」のWeb貼り付け画面を改善。分割コピーの順番と完了表示、全文の文字数、TXT保存と制作情報JSONの違いを明示しました。
アプリ：https://furuyan1234.github.io/nano-banana-pro/
解説：https://note.com/happy_duck780/n/ndf063558c1f5
#AIまんが #4コマ漫画 #ChatGPT
```

この投稿ではXホームの入力欄に下書きが残る場面があった。送信済み通知と公開ポストの両方を確認し、入力中に別のキー入力が混ざったため送信前に全文を照合し直した。Nano Banana Proのリリース・note・フルバックアップの証拠は [同アプリのHANDOFF](../HANDOFF.md) 冒頭にある。この文書の更新は当時のバックアップZIPより後なので、他PCではGitの履歴から取得する。
