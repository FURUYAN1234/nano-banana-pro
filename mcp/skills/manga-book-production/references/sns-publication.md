# 完成した漫画をSNSへ投稿する

完成作品の共有を希望された場合に使う。脚本だけの依頼、スキルの更新、アプリのデプロイ告知を、作品の投稿許可と解釈しない。投稿先・作者・アカウントを特定利用者の値へ固定しない。

## 希望と投稿先を確認する

1. 完成した採用ページを保存し、全ページをチャットへ表示した後、利用者からの催促を待たずAIから「この作品をSNSへ投稿しますか。投稿する場合は、どのSNSにしますか」と尋ねる。会話ですでに指定されていれば、その回答を引き継ぐ。「投稿しない」は尊重し、同じ作品で繰り返し勧めない。「下書きだけ」なら紹介文の提案までとする。
2. 投稿を希望されたら、SNS名と投稿するアカウント、公開範囲を確定する。複数のSNS・アカウントがある場合は対象を明示する。不足する項目だけをまとめて尋ね、作品のペンネームとログイン中のアカウント名を同一視しない。別利用者の名前・アカウント・リンクを流用しない。
3. 「投稿してよい」という意向と、具体的な投稿案への最終承認を分ける。投稿先も内容も未提示の段階で、公開まで承認されたと扱わない。今回の作品・宛先・本文・添付物について有効な承認がすでにあれば、同じ内容の再確認は不要。

## 接続を確かめる

- 利用できる正規のSNS接続・ブラウザー操作機能を調べ、必要な操作を行える経路を使う。利用者のブラウザー指定を尊重し、指定がなければ利用環境の既定方針に従う。特定サービスや拡張機能の存在を前提にしない。
- ブラウザー操作が必要で未接続なら、現在のツールが示す接続・タブ共有等の手順を利用者へ具体的に案内して、接続してもらう。未ログインなら対象SNSの通常のログイン画面を示し、利用者にログインを完了してもらう。パスワード、認証コード、APIキーをチャットへ貼るよう求めない。
- 接続済み・ログイン済みなら設定し直させない。接続完了の返答後、実際に対象画面を読み、投稿先のアカウントと操作可否を確認する。ブラウザー操作の接続とSNSのログインを混同しない。アカウントが違えば投稿しない。
- 保存済みの権限拒否を別経路で迂回しない。接続障害は原因を確認し、利用環境の方針で許可された代替手段があれば使う。接続待ちでも、作品と本文の準備は続けられる。漫画アプリの接続済みタブ・未保存作業を再読み込みや終了で失わない。

## 枕の文章と添付内容を提案する

- 現在の作品を読み、内容に合う短い導入文を考える。読みどころ、最新のタイトル、指定されたペンネームを自然に伝え、不要な結末の先取りや大げさな宣伝を避ける。別の旧案の設定・タイトルを混ぜない。利用者が本文を指定した場合はそれを優先する。
- 投稿のAI制作注釈は作品の実態に合わせる。AIが担当した工程と、人が行った確認・編集・指示を、確認できた範囲で記す。定型文の希望があれば、事実に沿う場合に使う。案内リンクは利用者が今回の投稿用に指定したものを使い、本文・注釈・URLを含めて対象アカウントの上限に収める。
- Xで最大20枚を添付できる環境では、5〜20枚でも本人が希望する1投稿に表紙から本文の順で全ページを添付する。4枚で区切る前提でスレッド化しない。送信前に投稿画面でアップロードが終わった画像を実際に数え、ページ順も照合する。アカウントやクライアントの制限が実際に出たときだけ、画面のエラーと受理済みの枚数を伝え、残りの扱いを調整する。 [X公式の画像枚数拡大案内](https://x.com/X/status/2121037816888963401)
- Facebookの個人フィードへの通常写真投稿では、可能な限り全ページを1投稿に表紙から読順どおりに添付する。公式ヘルプは複数の写真を選べると説明しており、通常投稿の一律上限を数値で示していない。アルバムは最大1,000枚で、この数値はアルバム全体に適用される。投稿画面が制限を示した場合は、投稿形式・表示内容・受理枚数を記録し、理由と残りのページをつなぐ具体的な分割方法を伝える。 [Metaの通常写真投稿ヘルプ](https://www.facebook.com/help/174641285926169) · [Metaのアルバム作成ヘルプ](https://www.facebook.com/help/214757948549570)
- 本文の文字数・画像枚数・形式は、各SNSで投稿に使うアカウントの契約や投稿形式に合わせる。利用者から長文機能の利用可否が示されていれば下書きの詳しさへ反映し、実投稿前に対象アカウントの通常の投稿画面と必要に応じて公式情報で受理条件を確認する。長文対応でも利用者の希望する長さを優先する。複数投稿が必要なら、表紙から本文までの読順、各投稿の文章・添付画像・続きのつなぎ方を提案する。無断でページを抜いたり、文字が読めなくなる縮小・切り抜きを行ったりしない。
- 保存済みの採用PNGを使い、添付は合意した素材に限る。設定画も指定された場合は採用済みの漫画全ページを読順で並べ、そのあとに採用済み設定画を合意した順で置く。投稿前のプレビューと公開後の実物で漫画・設定画の順序と枚数を照合する。投稿先で必要な変換がある場合も原本を保持し、文字の可読性と掲載順を確認する。Adobe等の別サービスや新しい画像生成を投稿準備へ自動追加しない。
- 添付前に今回の作品名と合意した読順を確認し、作品名とページが分かる投稿用の画像ファイルを絶対パスでリストにする。原本の名前が汎用の場合は作品名とページ順が分かる投稿用コピーを使う。ブラウザーのファイル選択ではイベントの待ち受けを先に登録し、添付ボタンを押して用意したパスを直接指定する。無関係なフォルダーを開いて探さない。全画像の読み込み後、プレビューを採用ページと照合して作品名・ページ順・枚数を確かめる。
- 投稿先ごとに、 **SNS／アカウント／公開範囲、実際に送る本文全文、添付画像と順番、投稿数・形式** をこのチャットに提示する。ハッシュタグ・リンク・メンションを使う場合も、提案文に含める。利用者が注釈やリンクの順番を指定した場合は反映する。それ以外の宣伝文や固定リンクを勝手に追加しない。
- 「この文章と画像を、この投稿先へ投稿してよいですか」と具体案へのOKを得る。無回答、接続したという返答、作品の生成承認を、投稿承認に読み替えない。修正を求められたら修正版を示す。承認後に投稿先・公開範囲・本文・添付ページを実質的に変える場合は、その変更を確認する。

- 添付ボタンは初回からファイル選択イベントの待ち受けと同じ操作単位で押す。開くかどうかを試すためだけに写真・動画ボタンを先押ししない。実ファイルの受理後もファイル選択画面が閉じたことを確認する。失敗・タイムアウト時はデスクトップの実状態を調べ、残った選択画面を閉じてから再試行や別SNSへ進む。確認のためだけにエクスプローラーを起動しない。

## 承認後に投稿し、実物を確認する

1. 承認した内容を正規の投稿画面・対応ツールへ反映する。最終送信前にアカウント、公開範囲、本文、画像数・順番、不要な下書きの混入がないことを照合する。同じ具体案へのOKを受けた後は、実際のツール制約が要求しない限り、投稿ボタンの直前に同じ確認を重ねない。
2. 承認された投稿・連続投稿だけを実行する。予約投稿、他SNSへの同時展開、広告出稿、固定、旧投稿の削除を無断で追加しない。
3. 投稿後に投稿の詳細画面または取得結果を読み戻し、対象アカウント・本文・画像・ページ順・公開範囲が承認案と一致するか確認する。XとFacebookでは公開後の投稿を開き、実際に添付された画像を数えて表紙から最終ページまで順番を照合する。投稿URLをチャットへ返す。送信を試したことやボタンの成功表示だけを、公開確認済みと扱わない。
4. 通信切断やタイムアウトで成否不明なら、同じ投稿を再送する前に対象アカウントの投稿一覧や投稿IDを確認する。成功済みなら再投稿しない。複数投稿の一部だけ完了した場合は、完了したURLと未完了分を分け、承認済みの残りだけを進める。確認できない場合は未確認と伝え、二重投稿を避ける。
5. 制作記録には対象SNS・アカウント・公開範囲、承認された本文とページの対応、承認の根拠、投稿ID／URL・確認結果を残す。接続情報や秘密情報は記録しない。漫画完成、投稿案完成、投稿承認、実投稿完了を別の状態として扱う。
